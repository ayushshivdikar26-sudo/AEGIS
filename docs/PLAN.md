## 1. Architectural Baseline & Decisions

Consolidated from `AEGIS_PRD.md` (Decisions Log D-01 through D-25) and source prompt documents:

1. **Clean Greenfield Reimplementation (D-01, D-16, D-19):**  
   No legacy Flask or SQLite code to port, maintain parity with, or migrate data from. No prototype database exists.
2. **Backend Architecture (D-01, D-20, D-21):**  
   FastAPI (Python 3.11+, tested on 3.13), Pydantic v2 schemas (`extra="forbid"`), Supabase Postgres for persistence, asymmetric JWKS verification for JWTs (`<SUPABASE_URL>/auth/v1/.well-known/jwks.json` cached with TTL, no HS256 path, algorithm allow-list).
   - Sync vs. Async Decision: **Sync `def` route handlers** using the official `supabase` Python client. FastAPI automatically executes sync `def` endpoints in an `anyio` worker threadpool, avoiding event loop starvation and eliminating async/sync impedance mismatches with `supabase-py`.
   - Client Token Isolation: Backend initializes base Supabase client with `SUPABASE_PUBLISHABLE_KEY` and `ClientOptions(persist_session=False, auto_refresh_token=False)`. User requests dynamically inject the caller's JWT (`client.postgrest.auth(token=user_jwt)`), ensuring database Row Level Security (RLS) policies evaluate against `auth.uid() = caller`. The `SUPABASE_SECRET_KEY` is isolated strictly in `app/admin.py` for test harness cleanup and admin tasks, never used for standard user data operations.
3. **Multi-Worker Shared Rate-Limiting (D-12, D-22):**  
   Slowapi with a Redis storage backend via `RATE_LIMIT_STORAGE_URI`. In `production`, startup fails if Redis URI is missing or if in-memory storage is selected. Critical mutation/auth endpoints (`login`, `signup`, `import`, `analyze`) fail closed (HTTP 503 `rate_limiter_unavailable`) if Redis becomes unreachable; read operations fail open with logged warnings.
4. **Deterministic Core Engine (D-17, D-18, PRD s4.11):**  
   All parsing, scoring, host pattern analysis, justification checks, and version comparisons reside in pure Python modules under `Backend/core/`. Pure functions, zero network or DB I/O, byte-identical deterministic outputs.
   - Explainability (FR-E1 to FR-E9): Every result includes rule IDs (`R1..R6`, `H1..H3`), calculation steps (formula, substituted values, result), creep triggers, source documentation links (Chrome/MDN), and review flags. `docs/RULES.md` is auto-generated by `scripts/gen_rules_doc.py` from configuration and tested for drift.
5. **Frontend Single-Page Architecture (D-02, D-14):**  
   Vanilla ES modules, pure CSS with strict 4px spacing tokens (`--s-1` to `--s-7`), deep indigo palette (`--bg: #07061A`), IBM Plex Sans / Mono fonts (self-hosted WOFF2). No build step or frontend frameworks. Zero `innerHTML` or dynamic script injection (`dom.js` builder with `textContent` only). Geometric placeholder logo mark and live-text wordmark (D-14). Animated background canvas (`threads.js`) with 30 FPS cap and `prefers-reduced-motion` compliance.
6. **AI Analyzer Deferred (D-04, D-17, D-25):**  
   Milestones M1 through M7 deliver the 100% complete rule-based auditor. Milestone M8 (Groq LLM explanation add-on) is strictly deferred until after M7 release. In M1-M7, `AI_ENABLED=false`, AI routes return HTTP 404 `ai_unavailable`, and no Groq environment variables are required.

### Milestone M1: Frontend UI & Dev Mock API
- **Goal:** Build the complete single-page application and mock server adhering strictly to the indigo design system, CSP, and accessibility rules without any live backend dependency.
- **Files to Create:**

  - `Frontend/assets/icons.svg`: Hand-drawn SVG sprite (search, chevron, close, menu, check).
  - `Frontend/assets/logo/placeholder-mark.svg`, `favicon.svg`: Flat indigo geometric mark (D-14).
  - `Frontend/css/tokens.css`: Color variables, typography tokens, base 4px spacing scale (`--s-1` to `--s-7`), border radius, transitions.
  - `Frontend/css/base.css`: Reset, `@font-face` definitions, base typography, universal focus ring (`--accent-text`).
  - `Frontend/css/layout.css`: Two-column layout (320px fixed sidebar, centered max 880px content), responsive drawer (<1024px), mobile layout (<600px).
  - `Frontend/css/components.css`: Risk chips (LOW, MED, HIGH, CRITICAL), version selectors, buttons, accordions, risk gauge styling.
  - `Frontend/css/motion.css`: Approved animation keyframes (load fade-up, needle transition, accordion slide, drawer slide) and comprehensive `prefers-reduced-motion: reduce` overrides.
  - `Frontend/js/threads.js`: Canvas generator drawing 18 strands (desktop) / 8 strands (mobile) on a shallow diagonal bundle with two passes (glow + core), capped at 30 FPS, paused on `document.hidden`, static frame on reduced-motion, SVG fallback.
  - `Frontend/js/dom.js`: Secure DOM builder `h(tag, attrs, ...children)`. Disallows `on*` attributes and style strings; forces `textContent`.
  - `Frontend/js/state.js`: Client-side state store (extensions list, search query, selected ID, section loading/error states).
  - `Frontend/js/api.js`: Standardized API client using `fetch`, relative URLs, `credentials: 'same-origin'`, AbortController per section, 10s timeout, custom error typing.

  - `Frontend/js/lib/filter.js`: Pure search filter matching extension names and browser names.

    - `sidebar.js`: Extension item rows, search input, clear button, polite count announcement, roving tabindex navigation.

  - `Frontend/js/main.js`: Bootstrap logic, hash routing (`#/ext/<id>`), keyboard handlers, drawer toggles.
  - `dev/mock-api/serve.py`: Standard library Python HTTP server binding to `127.0.0.1:8000`, serving `Frontend/` and fixture responses with strict CSP headers, supporting `?delay=` and `?fail=`.
  - `dev/mock-api/fixtures/*.json`: Fictional extensions fixture dataset covering happy paths, XSS name attempts, RTL text, 200-char strings, single snapshot, host broadening, and severe creep.
  - `tests/unit_js/`: `node --test` test files for `risk.js` and `filter.js`.
  - `tests/e2e/test_mock_frontend.py`: `pytest-playwright` suite verifying rendering, CSP enforcement, keyboard accessibility, responsive layouts, and state transitions.

### Milestone M2: Core Analysis Modules & Explainability Engine
- **Goal:** Implement the framework-free, pure Python analysis core with 100% deterministic output, complete rule traceability, and mathematical transparency.
- **Files to Create:**
  - `Backend/core/models.py`: Immutable Pydantic v2 data models (`ParsedManifest`, `MatchPattern`, `PermissionInfo`, `Assessment`, `Comparison`, `CreepAssessment`, etc.).
  - `Backend/core/manifest_parser.py`: Robust Manifest V2/V3 parser enforcing size limits (1 MB), depth limits (32), UTF-8 BOM handling, duplicate key rejection, placeholder resolution, bidi-character stripping, and structural feature detection (`features` set).
  - `Backend/core/host_patterns.py`: Chrome/MDN-compliant match pattern parser, covering `<all_urls>`, wildcard schemes, host hierarchy, scope tier classification (`single_host` to `all_sites`), and offline public suffix resolution.
  - `Backend/core/permission_rules.py`: Knowledge base loader validating `permission_knowledge.json`, weight lookups, and unreviewed flag tracking.
  - `Backend/core/risk_scoring.py`: Mathematical scoring engine computing $R_{api}$, $R_{host}$, base blend $S_{base}$, danger floors (40 for weight 4, 70 for weight 5), half-up rounding, top contributors breakdown, and step-by-step arithmetic trace (`calculation`).
  - `Backend/core/version_comparison.py`: Set-theoretic diffing of versions (`added`, `removed`, `retained`), host broadening detector (`covers(new, old)`), and creep outcome classifier with rule triggers.
  - `Backend/data/permission_knowledge.json`: Sourced knowledge base with weights 1-5, descriptions, legitimate uses, and Chrome/MDN documentation references.
  - `Backend/data/scoring_config.json`: Configuration constants (`formula_version="1"`, thresholds, default weights, delta thresholds).
  - `scripts/gen_rules_doc.py`: Documentation generator outputting `docs/RULES.md` directly from knowledge and config files.
  - `docs/RULES.md`: Catalogue of permissions, weights, and rules.
  - `docs/SCORING.md`: Mathematical formulation, thresholds, creep classification rules, and weight update guide.
  - `tests/core/`: Comprehensive pytest suite covering parser edge cases, match pattern properties (`hypothesis`), scoring goldens (Golden 1, 2, 3), comparison goldens, 100-run determinism test, and stale `RULES.md` validation.
- **Exit Criteria:**
  - $\ge 90\%$ code coverage on `core/`.
  - `ruff` and `mypy` clean.
  - Exact match on all 3 Golden scoring tests and Golden comparison test.
  - Determinism test passes (100 runs byte-identical).

### Milestone M3: Supabase Database Schema, RLS & Database Test Suite
- **Goal:** Create production-ready SQL migrations, enforce strict Row Level Security, configure private icon storage, and verify isolation with a two-user test suite against the dev Supabase project (no Docker required).
- **Files to Create:**
  - `supabase/migrations/0001_init.sql`: Table schemas for `extensions` and `extension_snapshots`, unique constraints, foreign keys with cascade delete, and updated-at triggers.
  - `supabase/migrations/0002_rls.sql`: RLS enablement and force directives on all tables, selective authenticated-only policies with `(select auth.uid())`, complete revocation of permissions from `anon`, immutability trigger preventing snapshot updates, and quotas (500 extensions per user, 100 snapshots per extension).
  - `supabase/migrations/0003_storage.sql`: Private bucket `extension-icons`, MIME restriction (`image/png`, `image/jpeg`, `image/webp`), 256 KB file size limit, path policy `user_id/extension_id.ext`.
  - `docs/SUPABASE_SETUP.md`: Manual configuration guide for dev and prod projects (asymmetric JWT verification settings, keys, bucket configuration, auth policies).
  - `docs/DATABASE.md`: Entity-relationship diagram (Mermaid) and data dictionary.
  - `tests/db/test_supabase_rls.py`: Two-user Pytest suite executing against the dev Supabase project using real user JWTs, validating all 11 security isolation checks from PRD s11.5.
- **Exit Criteria:**
  - All 11 DB isolation tests pass against the dev Supabase project with real outputs logged.
  - Immutability and quota triggers verified.
  - User A cannot access User B data via client queries or direct REST calls.

### Milestone M4: FastAPI Backend, Auth, Import, Security Controls & Wiring
- **Goal:** Connect frontend and backend with production security controls, streaming multipart manifest import, JWKS asymmetric auth, and multi-worker rate limiting.
- **Files to Create/Update:**
  - `Backend/app/config.py`: Pydantic settings loading and validating environment variables, rejecting insecure options in production.
  - `Backend/app/security.py`: Asymmetric PyJWT token validation via cached Supabase JWKS endpoint with key rotation handling, secure cookie extraction, and double-submit CSRF verification (`X-AEGIS-CSRF`).
  - `Backend/app/deps.py`: FastAPI dependency injectors (`get_current_user`, `get_user_db_client`, rate limiting key functions).
  - `Backend/app/errors.py`: Global exception handlers formatting all errors to `{"error": {"code", "message", "request_id"}}` with zero trace leakage.
  - `Backend/app/middleware.py`: Security headers middleware (CSP, HSTS, X-Content-Type-Options, COOP, Cache-Control: no-store), request ID tracing, and streaming request size limiter (1.5 MB total limit).
  - `Backend/app/logging_setup.py`: Structured JSON logger with automated credential/token redaction.
  - `Backend/app/schemas.py`: Pydantic v2 API contract models (`extra="forbid"`).
  - `Backend/app/repo.py`: Single data access layer executing queries with the user-scoped Supabase client.
  - `Backend/app/admin.py`: Isolated admin module using secret key (no normal user routes invoke this).
  - `Backend/app/services/assessment.py`: Bridge transforming DB snapshots into `core` models and evaluating risk assessments.
  - `Backend/app/services/justification.py`: Stub returning `status: "unknown"` ("Justification checker not installed yet").
  - `Backend/app/services/ai.py`: Stub returning `capabilities.ai_analysis = false`.
  - `Backend/app/routers/`:
    - `health.py`: Public health check (`GET /api/health`).
    - `auth.py`: `signup`, `login`, `refresh`, `logout`, `me` endpoints setting HttpOnly cookies.
    - `extensions.py`: CRUD operations for extensions, permissions, versions, comparison, and creep.
    - `imports.py`: Multipart import endpoint with magic-byte icon validation, deduplication, and snapshot storage.
  - `Backend/app/main.py`: FastAPI app initialization, middleware wiring, routers mounting, and static file mount for `Frontend/` (with strict 404s on sensitive directories).
  - `Frontend/js/api.js`: Updated to target live endpoints with `X-AEGIS-CSRF` header.
  - `Frontend/js/render/states.js`: Integrated auth modal view, import modal dialog, delete confirmation dialog, and 429 Retry-After timer display.
  - `tests/app/`: Test suite for routes, auth, ownership checks, CSRF, rate-limiter shared store, and file upload validation.
  - `tests/e2e/test_real_backend.py`: Playwright tests running end-to-end against the live backend and dev Supabase.
- **Exit Criteria:**
  - All API routes pass contract validation tests.
  - CSRF, auth failure, and rate limiting (429) verified across two uvicorn workers.
  - Import handles valid, invalid, duplicate, and conflict manifests.
  - End-to-end Playwright tests pass green against live backend.
